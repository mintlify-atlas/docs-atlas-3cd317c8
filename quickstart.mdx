---
title: "Get up and running with Caddy Proxy Manager quickly"
description: "Deploy Caddy Proxy Manager with Docker Compose, configure your credentials, and create your first reverse proxy host in under five minutes."
---

Caddy Proxy Manager runs entirely in Docker. You clone the repository, set three required environment variables, start the stack, and log in — Caddy handles TLS automatically from that point on. This guide walks you through each step and explains what the optional ClickHouse and GeoIP profiles add.

## Prerequisites

- [Docker Engine](https://docs.docker.com/engine/install/) 24 or later
- [Docker Compose](https://docs.docker.com/compose/install/) v2 (the `docker compose` plugin, not the standalone `docker-compose` command)
- Ports 80, 443, and 3000 available on the host

## Deploy the stack

<Steps>
  <Step title="Clone the repository and copy the example env file">
    ```bash
    git clone https://github.com/fuomag9/caddy-proxy-manager.git
    cd caddy-proxy-manager
    cp .env.example .env
    chmod 600 .env
    ```

    The `.env` file holds all configuration. `chmod 600` restricts it to your user only — important for production.
  </Step>

  <Step title="Set your credentials">
    Open `.env` in an editor and set the three required variables:

    ```env
    # Generate with: openssl rand -base64 32
    SESSION_SECRET=your-secure-session-secret-min-32-chars

    ADMIN_USERNAME=admin
    ADMIN_PASSWORD=YourStr0ng-P@ssw0rd123!
    ```

    **`SESSION_SECRET`** encrypts session cookies. Generate a strong value with:

    ```bash
    openssl rand -base64 32
    ```

    **`ADMIN_PASSWORD`** must meet these requirements in production:
    - 12 or more characters
    - At least one uppercase letter (A–Z)
    - At least one lowercase letter (a–z)
    - At least one number (0–9)
    - At least one special character (`!@#$%^&*` etc.)

    <Warning>
      The Docker Compose file will refuse to start if `SESSION_SECRET`, `ADMIN_USERNAME`, or `ADMIN_PASSWORD` are missing. Development mode (`NODE_ENV=development`) allows the default `admin`/`admin` credentials, but this is never acceptable in production.
    </Warning>
  </Step>

  <Step title="Start the stack">
    ```bash
    docker compose up -d
    ```

    Docker pulls the images and starts the containers. The `web` container waits for `caddy` to pass its health check before it starts. First startup takes about 30–60 seconds.

    Check that all containers are running:

    ```bash
    docker compose ps
    ```
  </Step>

  <Step title="Log in to the dashboard">
    Open [http://localhost:3000/login](http://localhost:3000/login) in your browser and sign in with the `ADMIN_USERNAME` and `ADMIN_PASSWORD` you set in `.env`.

    <Note>
      If you changed `BASE_URL` in `.env` to a custom domain or IP, use that address instead of `localhost`.
    </Note>
  </Step>

  <Step title="Create your first proxy host">
    1. Navigate to **Proxy Hosts** in the sidebar.
    2. Click **Add Proxy Host**.
    3. Enter the **Domain Name** you want to proxy (for example, `app.example.com`).
    4. Set the **Upstream** to your backend address (for example, `http://192.168.1.10:8080`).
    5. Toggle **Force HTTPS** if you want Caddy to redirect HTTP traffic.
    6. Click **Save**.

    Caddy automatically requests a TLS certificate from Let's Encrypt for the domain. The certificate appears under **Certificates** once it is issued (usually within a few seconds if the domain points to this server).
  </Step>
</Steps>

## Optional profiles

The default `.env.example` activates the `clickhouse` profile. You can combine profiles by separating them with commas.

```env
# Enable analytics only (default)
COMPOSE_PROFILES=clickhouse

# Enable analytics and automatic GeoIP database updates
COMPOSE_PROFILES=clickhouse,geoipupdate

# Disable all optional services
COMPOSE_PROFILES=
```

### ClickHouse (analytics)

The `clickhouse` profile starts a ClickHouse container that stores traffic events and WAF events with a 90-day retention TTL. When active, you also need to set `CLICKHOUSE_PASSWORD`:

```env
CLICKHOUSE_PASSWORD=your-clickhouse-password   # openssl rand -base64 32
```

Without the `clickhouse` profile, the Analytics page shows a notice that analytics is not enabled and no data is collected.

### GeoIP update

The `geoipupdate` profile starts a MaxMind GeoLite2 updater that refreshes the country and ASN databases every 72 hours. Geo blocking requires these databases. To use it:

1. Register for a free MaxMind account at [maxmind.com](https://www.maxmind.com/).
2. Generate a license key with `GeoLite2-Country` and `GeoLite2-ASN` permissions.
3. Add your credentials to `.env`:

```env
GEOIPUPDATE_ACCOUNT_ID=your-account-id
GEOIPUPDATE_LICENSE_KEY=your-license-key
```
