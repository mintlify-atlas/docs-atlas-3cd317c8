title: "Audit Log API: query paginated configuration history"
description: "Query the Caddy Proxy Manager audit log via GET /api/v1/audit-log. Supports page, per_page, and search parameters. Returns events with user attribution."
---

The audit log records every significant action taken in Caddy Proxy Manager — proxy host changes, certificate operations, settings updates, login events, and more. The API exposes a single paginated endpoint so you can query the log programmatically, stream it into a SIEM, or build custom dashboards. All requests require admin-level authentication.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/audit-log` | List audit log events |

---

## GET /api/v1/audit-log

Returns a paginated list of audit log events, optionally filtered by a search term.

### Query parameters

<ParamField query="page" type="integer" default="1">
  Page number to retrieve. Pages are 1-indexed. Requesting a page beyond the last page returns an empty `events` array.
</ParamField>

<ParamField query="per_page" type="integer" default="50">
  Number of events to return per page. Larger values reduce the number of round trips but increase response size.
</ParamField>

<ParamField query="search" type="string">
  Free-text search term. When provided, results are filtered to events where the `action`, `entity_type`, or `summary` fields contain the search string (case-insensitive). See [search behaviour](#search-behaviour) below.
</ParamField>

<CodeGroup>

```bash First page, default page size
curl -X GET "https://your-instance:3000/api/v1/audit-log" \
  -H "Authorization: Bearer <token>"
```

```bash Page 2, 25 events per page
curl -X GET "https://your-instance:3000/api/v1/audit-log?page=2&per_page=25" \
  -H "Authorization: Bearer <token>"
```

```bash Search for proxy host events
curl -X GET "https://your-instance:3000/api/v1/audit-log?search=proxy_host" \
  -H "Authorization: Bearer <token>"
```

</CodeGroup>

**`200 OK`**

```json

      "created_at": "2024-06-01T14:23:00Z"

    {
      "id": 41,

      "entity_type": "settings",
      "entity_id": null,
      "summary": null,
      "created_at": "2024-06-01T14:20:00Z"

  "perPage": 50
```

### Top-level response fields

<ResponseField name="events" type="object[]" required>
  Array of audit log event objects for the current page.

  <Expandable title="AuditLogEvent properties">
    <ResponseField name="id" type="integer" required>
      Unique numeric identifier for this event record.
    </ResponseField>

    <ResponseField name="user_id" type="integer | null">
      ID of the user who triggered the action. `null` for system-generated events (e.g. automatic certificate renewal).
    </ResponseField>

    <ResponseField name="action" type="string" required>
      Machine-readable action name describing what happened (e.g. `proxy_host_created`, `certificate_deleted`, `settings_updated`).
    </ResponseField>

    <ResponseField name="entity_type" type="string" required>
      The type of resource affected by the action (e.g. `proxy_host`, `certificate`, `settings`, `user`).
    </ResponseField>

    <ResponseField name="entity_id" type="integer | null">
      The numeric ID of the affected resource. `null` for actions that do not target a specific record (e.g. global settings changes).
    </ResponseField>

    <ResponseField name="summary" type="string | null">
      A short human-readable description of the event. May be `null` for older events or system actions that do not generate a summary.
    </ResponseField>

    <ResponseField name="created_at" type="string" required>
      ISO 8601 timestamp of when the event was recorded.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="total" type="integer" required>
  Total number of events matching the current query (including all pages). Use this value together with `perPage` to calculate the total number of pages: `Math.ceil(total / perPage)`.
</ResponseField>

<ResponseField name="page" type="integer" required>
  The current page number returned.
</ResponseField>

<ResponseField name="perPage" type="integer" required>
  The number of events per page used for this response.
</ResponseField>

## Pagination

The audit log uses offset-based pagination. Use `total` and `perPage` to determine how many pages exist, then iterate by incrementing `page`.

```bash Iterate all pages
# Page 1
curl "https://your-instance:3000/api/v1/audit-log?per_page=100&page=1" \
  -H "Authorization: Bearer <token>"

# Page 2
curl "https://your-instance:3000/api/v1/audit-log?per_page=100&page=2" \
  -H "Authorization: Bearer <token>"

# Continue until 'events' is empty or page > ceil(total / per_page)
```

Events are returned in reverse-chronological order (newest first). There is no cursor-based pagination; if new events are written while you are iterating, later pages may shift by one position.

## Search behaviour

When `search` is supplied, the API performs a case-insensitive substring match against the `action`, `entity_type`, and `summary` fields. This lets you quickly filter by:

- **Action verb** — e.g. `search=deleted` returns all deletion events
- **Resource type** — e.g. `search=certificate` returns all certificate-related events
- **Free text in summaries** — e.g. `search=example.com` finds events mentioning that domain

<Note>
  Search is applied server-side before pagination. The `total` field in the response always reflects the count of matched events, not the total number of events in the log.
</Note>

Search does not currently support field-specific filtering, boolean operators, or regex patterns. For more complex filtering, retrieve all events with a broad search and filter client-side.
